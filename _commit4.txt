chore(engineering): 补齐工程外观件（Docker / CI / pyproject / Makefile）

背景：
  代码与评测都已就绪，但缺"工程化外观"这一类能让项目看起来专业的东西。
  按需求补齐以下八项，并各自说明取舍理由。

新增：
  - pyproject.toml  依赖分层是核心设计，不是随手列包名：
                      （无）  -> core/ 里 17 个模块纯标准库
                      core    -> 向量库与 LLM SDK（延迟导入）
                      ml      -> torch / transformers / FlagEmbedding
                      serve   -> FastAPI
                      dev     -> 测试与工具链
                    dependencies 显式留空 + 测试断言守护，
                    这样 CI 才能不装 torch 就跑到全部核心测试。

  - Dockerfile      多阶段 + 非 root + healthcheck。三个取舍都写在注释里：
                      ① slim 而非 nvidia/cuda：GPU 由宿主机提供，
                        镜像只负责"可复现地把服务跑起来"，体积 7GB -> 2GB
                      ② 先 COPY pyproject 再 COPY 源码：保住依赖层缓存
                      ③ 模型与数据用 volume 挂载，不打进镜像
                    并把 transformers 锁在 4.44.2（见下）

  - .dockerignore   .env 是必须项，不是可选项：镜像层不可变，
                    打进某一层后即使下一层删除，仍留在 history 里可被 pull。

  - docker-compose.yml  模型只读挂载、env_file 引用 .env（不内联密钥）、
                    healthcheck 给 90 秒 start-period（装配要加载两个模型）。

  - Makefile        把十几条易记错的命令固化（建库/消融/对比 run/网格搜索/
                    评测集体检）。★ PY 与 PY2 刻意分开：
                    PY 跑 core 与测试（零依赖），PY2 跑真模型与真 API ——
                    合并之后"验证代码是否正确"就依赖环境，
                    环境装不上就什么都验不了。

  - .github/workflows/ci.yml  5 个 job。核心主张是**它跑得极快**：
                    core/ 零依赖可测，所以 CI 不装 torch、不下模型、
                    不要 API Key，整个 job 通常 30 秒内结束。
                    另有三个针对性 job：
                      reproducibility 同 seed 两次生成的语料必须逐字节一致
                                      （"可复现评测"的机器可验证证据）
                      secret-guard    全量历史扫描 .env 与硬编码密钥
                                      （防"提交过又删掉"）
                      lint            ruff，暂设 continue-on-error

  - rag1_knowledge_qa/server.py  uvicorn 入口。api_fastapi 用的是 app factory
                    模式（便于注入假 service），但 uvicorn 的 module:app 约定
                    需要模块级 app，这个文件把两者接起来；另外把装配失败
                    变成可读的排查步骤，而不是一大段 import traceback。

  - tests/test_engineering_config.py  36 项测试，把这些配置的**契约**固化：
                      · .env.example 必须覆盖 bootstrap.DEFAULTS 全部变量，
                        且两边默认值一致（否则用户照抄后行为与文档不符，
                        却不报错）
                      · docker-compose 的容器内路径必须与 DEFAULTS 对得上
                      · Dockerfile 必须锁 transformers==4.44.2
                      · CI 里不得出现 pip install torch/chromadb/langgraph
                      · CI 内嵌的 <<'PY' 脚本必须能 compile
                      · Makefile 配方行必须用 Tab（且能区分反斜杠续行）
                      · 目标不得与同名目录冲突（未声明 .PHONY 时
                        make 会报 "'x' is up to date" 这种迷惑错误）
