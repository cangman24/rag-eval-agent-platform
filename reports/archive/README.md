## ⚠️ `run-20261016-100221-991c15` 的两个已知口径问题

这份报告曾被 README 引用，但它**不能自证**：

1. **语料 82 篇而非 83 篇**：`data/raw/data_process.md` 当时未产出任何 chunk
   （通篇是编号列表，切分时被整篇判成标题结构 → 0 块，且当时没有报警）。
   该 bug 已修（见 `core/ingest.py` 的兜底与 `docs_without_chunks` 统计），
   当前索引为 **83 篇 / 303 块**。
2. **`ingest.embedding_model` 为 `unknown`**：当时的建库参数没有被写进 manifest，
   所以这份报告无法回答"它是哪套参数、哪个模型跑出来的"。

结论：**引用数字请用 [`../latest/`](../latest/)**，它的 manifest 带
`model_info`（模型名 / 向量维度实测 / 精排是否加载）与
`corpus_fingerprint`（语料篇数 + 内容 sha256 + 入索引篇数），
可用 `python tools/verify_evidence_chain.py reports/latest` 一键校验。

> 这两条问题本身就是"为什么要建证据链"的最好说明：
> 一份报告如果没记录它跑在什么上面，它的数字就只能靠回忆支撑。
