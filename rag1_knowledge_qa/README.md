# 基于 RAG 的垂直领域知识问答系统

> 面向**领域文档分散、术语密集、答案口径不一致**的场景，构建可溯源、可评测、可自维护的知识问答系统。
> 支持混合检索（BM25 + 向量 + RRF 融合 + 交叉编码精排）、父子块双层索引、低置信拒答与引用溯源。

**核心指标**（在自建评测集上、逐层消融）：

| 配置 | Hit@5 | MRR@5 | NDCG@5 |
|---|---|---|---|
| 纯向量检索 | 0.8750 | 0.6219 | 0.6858 |
| + BM25 / RRF 混合 | 1.0000 | 0.8385 | 0.8789 |
| + Reranker 精排 | 1.0000 | 0.9271 | 0.9457 |
| + 编号规则召回 | 1.0000 | 0.9271 | 0.9457 |

> ⚠️ 上表为**演示链路**跑出的结果（4 篇文档 / 9 个子块 / 18 条评测集，嵌入为哈希假实现），
> 用于验证消融框架能把各模块贡献拆开。**替换为 BGE-M3 + bge-reranker-v2-m3 后需重跑**，
> 届时以 `reports/` 下的真实报告为准。

## 1. 解决的四个真实问题

| # | 问题 | 方案 |
|---|---|---|
| 1 | 文档格式与层级复杂，**固定切分导致语义断裂**，召回噪声大 | 递归切分 + 标题层级保留 + **父子块双层索引** |
| 2 | 纯向量检索对**专有名词、编号、型号**命中率低 | **BM25 + 向量双路召回**，RRF 融合；编号/型号走规则召回 |
| 3 | 长文档超出上下文窗口，**模型产生幻觉且答案无法追溯** | **低置信拒答** + Prompt 强制**引用原文片段** |
| 4 | 检索调参依赖人工，**缺少可量化、可回归的评测手段** | 自建评测集 + **逐层消融实验** + 分类型统计 + Badcase 回流 |

## 3. 代码结构

```
core/                             # ★ 已验证的核心（420+ 单测，零第三方依赖）
├── loaders.py      多格式解析（依赖可选，坏文件不中断整批）
├── retrieval.py    递归切分（标题层级）+ RRF 融合
├── text.py         中文分词（单字 + bigram）+ 文本归一化
├── bm25.py         BM25 自实现（min_score 阈值过滤）
├── vectorstore.py  向量库抽象 + 内存实现 + ChromaDB 实现
├── ingest.py       建库流水线（父子块 + 双索引 + 配置指纹）
├── pipeline.py     检索编排（各路可开关，内置 4 档消融配置）
├── metrics.py      Hit@K / MRR / NDCG / 拒答正确率 / 幻觉率
├── evaluation.py   评测框架（体检 / 消融 / 报告 / Badcase 清单）
├── llm.py          LLM 客户端（重试 / 限流 / 磁盘缓存）+ 引用 Prompt
├── mcp.py          MCP 风格工具层（Schema 自动生成 + 白名单）
├── agent.py        Agent 状态机（Checkpoint 续跑 + 三道熔断）
├── memory.py       三层记忆 + 三级上下文压缩
├── sse.py          SSE 协议（帧格式化 + 往返校验）
└── service.py      框架无关的服务层（问答 / 拒答 / 轨迹）

rag1_knowledge_qa/                # 本项目
├── bootstrap.py    生产装配（需 GPU + BGE 模型 + DeepSeek Key）
├── api_fastapi.py  HTTP / SSE 接口（薄适配）
└── cli.py          命令行入口（不装 fastapi 也能用）
```

> **设计要点**：业务逻辑全在 `core/`，`rag1_knowledge_qa/` 只做装配与传输。
> 因此 CLI 与 HTTP 走**同一条代码路径**，不会出现"接口和命令行行为不一致"。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查 + 索引规模 |
| POST | `/chat` | 一次性问答 `{"query": "..."}` |
| POST | `/chat/stream` | SSE 流式问答 |
| GET | `/chat/stream?q=` | SSE 流式（浏览器 `EventSource` 可直接联调） |
| GET | `/debug/retrieve?q=&top_k=` | **只检索不生成** —— 调检索参数最常用 |
| GET | `/debug/service` | 服务自描述（配置指纹） |

**SSE 事件类型**（前端轨迹面板按此渲染）：

```
start → intent → plan → tool_call → tool_result → verify → answer → done
                        └─ tool_error（被白名单拦截）
                        └─ refusal（低置信拒答，此时**不发** citation）
```

每条帧带自增 `id`，前端断线重连时通过 `Last-Event-ID` 续发。

## 6. 关键设计决策（面试可讲）

### 6.1 为什么用 RRF 而不是加权求和

BM25 分数范围 `[0, +∞)`，向量相似度范围 `[-1, 1]`，**两者量纲不可比**。
加权求和要么先归一化（对分数分布敏感、需反复调权重），要么直接相加（BM25 会完全压制向量分数）。
RRF 只用排名 `1/(k+rank)`，天然免疫量纲问题且几乎免调参。

### 6.2 为什么"先切父块，再在父块内切子块"

最初我写的是"在全文上切子块，再用字符串位置反查归属父块"——**这是脆弱启发式**：
文本可能重复出现、overlap 会让边界模糊，定位一错父子关系就错，回吐的上下文全是别的章节。
改成嵌套切分后归属关系是**结构性确定**的。代价是父块边界限制子块跨度，
但对章节式文档反而更好——子块永不跨章节。

### 6.3 中文 BM25 的固有噪声与 `min_score`

中文走单字 + bigram 切分时，**任何中文查询几乎总能撞上几个高频单字**（"的"、"不"、"是"），
这些字 IDF 很低但非零，会让无关文档拿到正分。实测噪声分 1.09，而相关查询在 6~8 量级。
所以检索层加了分数下限过滤——它等价于一次"低置信拒答"。

### 6.4 拒答判定必须用固定话术，不能只搜关键词

真实踩坑：用户问"精度要求是多少"，模型答"精度要求为 0.90"——若只搜 `未找到` 会误判。
但换成搜**完整话术「知识库中未找到」并要求出现在回答前 60 字符内**，就既不会误伤
正常回答，也能识别真拒答。

### 6.5 引用只在确定作答后才推送

初版 SSE 在生成答案**之前**就把 citation 推给前端了。结果是"拒答"场景下
前端已经渲染了 3 条来源——用户看到"未找到"的回答配着引用，自相矛盾。
正确顺序：检索 → 生成/判定 → （不拒答才发 citation）→ answer → done。

## 7. 评测口径（★ 面试必答）

| 指标 | 正确口径 | 常见错误 |
|---|---|---|
| **MRR@K** | `1/rank`，**1-based**（第 3 位 = 1/3） | 用 0-based，MRR 虚高 |
| **Precision@K** | 分母**固定为 k** | 用"实际返回条数"当分母 |
| **Hit@K** | 前 K 条命中任一 gold 即 1 | 与 Recall 混用 |
| **幻觉率** | 忠实度**严格小于**阈值才计（`< 3`） | 用 `<=`，把边界算进去 |
| **召回 ≠ 准确** | 检索层报 Hit@5/MRR，生成层报忠实度/幻觉率，**分开报** | 混成一个"准确率" |
